# 배포

첫 수동 배포는 [Ubuntu 최초 배포 안내](first-deployment.md)를 순서대로 따른다.

현재 상태: 계획 단계이며 아직 배포하지 않았다.
CI 워크플로는 정적 빌드 결과를 검증하고 아티팩트로 업로드하며, 서버에는 접속하지 않는다.

## 계획한 배포 환경

- Oracle Cloud VM에서 Nginx로 `apps/web/dist/`를 제공한다.
- 실제 도메인의 DNS가 VM을 가리키도록 설정한다.
- Let's Encrypt로 HTTPS 인증서를 관리하고 갱신 동작을 검증한다.
- GitHub Actions의 비밀정보 저장소에 최소 권한의 SSH 자격 증명을 보관해 배포한다.

## 남은 설정

1. VM 운영체제, 호스트명, 배포 사용자, 도메인과 배포 경로를 확정한다.
2. 방화벽 규칙, SSH 접근과 Nginx 가상 호스트를 설정한다.
3. 디렉토리의 인덱스 페이지를 제공하고, 없는 경로에는 생성된 `404.html`을 반환한다.
4. HTTPS를 설정하고 인증서 갱신을 검증한다.
5. 버전별 릴리스 디렉토리, 현재 릴리스의 원자적 전환, 기본 동작 확인,
   이전 릴리스로의 롤백을 구현한다.
6. 배포 대상과 자격 증명을 준비한 뒤 CI에 배포 단계를 추가한다.

`infra/nginx/bang-lab.conf`는 HTTP 초기 설정 템플릿이다.
실제 도메인과 정적 파일 경로로 변경하고, 서버의 Nginx 설정 디렉토리에 설치한다.
`root`에는 저장소 전체가 아닌 `apps/web/dist/` 내용만 배치한다.
없는 경로는 HTTP 404와 사용자 정의 오류 페이지를 반환하며, HTML은 재검증하고
해시가 붙은 Astro 자산은 장기 캐시한다. 숨김 파일 접근은 차단한다.
템플릿 자체에는 HTTPS 인증서와 리다이렉트가 없으므로 공개 전에 별도로 설정한다.
서버에서 `nginx -t` 성공을 확인한 뒤 설정을 적용한다.
개인 키, 접근 토큰과 실제 비밀정보를 커밋하지 않는다.
로컬 빌드 성공만으로 배포, HTTPS 또는 롤백이 동작한다고 판단하지 않는다.

## 빌드 환경변수

GitHub 저장소의 Settings → Secrets and variables → Actions에서
`CONTACT_EMAIL`, `PROFILE_NAME`을 repository secrets로 등록한다.
현재 워크플로는 `main` 브랜치의 push 빌드에만 해당 값을 전달한다.
PR 빌드는 개인정보 없이 검증하며, secrets가 없어도 기본 상태로 빌드된다.
실제 원격 secrets 등록은 아직 수행하지 않았다.

로컬에서는 `apps/web/.env`를 사용한다. 이 파일은 Git과 배포 파일에 포함하지 않는다.
Astro 빌드 시 값을 HTML에 반영하므로 Nginx에 환경변수만 설정해서는 값이 바뀌지 않는다.
변경 후 다시 빌드·배포해야 한다. 생성 HTML 및 업로드된 빌드 아티팩트에는 표시 값이 포함된다.
이 변수에는 방문자에게 공개할 정보만 넣고 비밀번호나 API 키를 넣지 않는다.
