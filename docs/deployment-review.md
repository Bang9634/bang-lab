# 최초 배포 준비 점검

점검일: 2026-09-08.

## 판단

현재 앱은 정적 사이트의 초기 공개용으로 사용할 수 있다.
이번 점검 범위에서 앱 실행이나 정적 파일 제공을 막는 결함은 발견하지 않았다.
다만 실제 Oracle VM의 도메인·HTTPS·파일 경로·권한을 검증하지 않았으므로
현재 저장소만으로 운영 배포가 완료되거나 자동화됐다고 볼 수는 없다.
About / Work / Contact는 준비 중 문구이며, 완성된 포트폴리오가 아닌 초기 공개 상태이다.

## 배포 전에 필요한 사항

| 우선순위 | 항목 | 확인 결과와 필요한 조치 |
| --- | --- | --- |
| 필수 | 실제 호스팅 설정 | Nginx 템플릿의 `server_name`, `root`를 실제 값으로 바꾸고, `dist/` 내용만 서비스한다. 서버 파일 권한과 `nginx -t`도 확인한다. |
| 필수 | HTTPS | 현재 템플릿은 HTTP 초기 설정이다. 도메인/DNS, 인증서 발급·갱신, HTTP → HTTPS 전환은 운영 서버에서 구성·검증해야 한다. |
| 필수 | 배포 방식 | CI는 검사·빌드·아티팩트 업로드만 수행한다. 최초에는 검증된 빌드 결과를 수동 배포할 수 있으며, 자동 배포는 이후 구현해도 된다. |
| 조건부 | 표시 정보 | CI에서 이름·이메일을 출력하려면 Actions secrets를 등록한다. 미설정 상태도 정상 빌드되지만 이메일은 숨겨지고 이름은 브랜드명으로 대체된다. |
| 필수 | 공개 범위 | 환경변수로 출력한 값은 최종 HTML과 아티팩트에 포함된다. 소스·문서·라이선스의 정보는 별도로 검토한다. `.env` 제외가 기존 커밋을 지우지는 않는다. |
| 필수 | 운영 로그 | 서버의 실제 access/error 로그 항목과 보관 정책을 확인한다. 애플리케이션에 폼이나 분석 도구가 없다는 사실만으로 서버도 아무것도 기록하지 않는다고 판단하지 않는다. |

## 점검 중 수정

- `pagehide`에서 타이핑 타이머를 중지하고, 뒤로가기 캐시 복귀 시 다시 시작하도록 수정했다.
  이전에는 초기 스크립트가 재실행되지 않는 복귀 상황에서 타이핑이 멈출 가능성이 있었다.
- 빈 터미널 문구에서는 불필요하게 타이머를 반복 예약하지 않도록 처리했다.
- 빈 Nginx 파일에 정적 호스팅용 HTTP 템플릿을 추가했다.
  없는 경로는 사용자 정의 404, 숨김 파일은 차단, HTML은 재검증,
  해시 자산은 장기 캐시하도록 설정했다.
- CI에 10분 제한 시간을 설정했다.

## 실행한 검증

- `npm run check`: 오류·경고·힌트 없음.
- `npm run build`: 홈과 404 생성 성공.
- `npm ls --depth=0`: 직접 의존성 설치 상태 정상.
- `npm audit`: 점검 당시 알려진 취약점 0건. 보안 문제가 전혀 없다는 보장은 아니다.
- `.env`, `dist`, `node_modules`의 Git 제외 상태 확인. `.env.example`은 포함 가능.
- 임시 로컬 Nginx에서 템플릿 문법 검사 및 실제 HTTP 요청 수행:
  홈 200, 자산 MIME와 캐시, HTML 재검증, 없는 경로·삭제된 페이지 404,
  사용자 정의 오류 본문, `.env` 403 응답 확인.
- 빌드 결과에 소스 README/package.json, `.env`, 소스맵이 없는지 확인.
- 생성 HTML의 내부 앵커 대상이 모두 존재하는지 확인.
- 가상 타이머로 타이핑·삭제·반복, 반복된 뒤로가기 캐시 복귀,
  탭 숨김과 복귀, 동작 줄이기 설정, 빈 문구 처리 검증.
- 환경변수 미설정, 설정된 이메일의 메일 링크, 이름의 HTML 이스케이프,
  잘못된 이메일의 값 노출 없는 빌드 실패 확인.
- 검증용 값은 최종 빌드 전에 제거하고 로컬 설정으로 다시 빌드했다.
- 검증용 임시 Nginx는 종료했다.

## 남은 검증과 개선

- 연결 가능한 브라우저가 없어 실제 렌더링·클릭·키보드·모바일·Safari 검증은 수행하지 못했다.
  가상 타이머 검증이 실제 브라우저의 캐시 수명주기와 렌더링 검증을 대체하지는 않는다.
- 로컬 Node.js 26에서 검증했다. CI의 Node.js 24 및 새 Linux 환경에서의
  `npm ci`·빌드 성공은 첫 GitHub Actions 실행으로 확인해야 한다.
- 실제 Oracle VM, DNS, TLS, 인증서 갱신과 운영 환경 권한은 확인하지 않았다.
- 연속 타이핑을 직접 일시정지하는 UI는 없다. 동작 줄이기 설정은 지원하지만,
  접근성 수준을 높이려면 별도 정지 수단과 회색 소형 글자의 대비를 검토한다.
- 도메인 기반 canonical/og:url, favicon, 소셜 공유 이미지는 후속 개선 대상이다.
- 첫 로드의 해시 제거는 사용자가 요청한 동작이다. 외부에서 `/#work`로 접근해도
  최상단부터 시작하므로 특정 섹션 직접 공유는 현재 지원하지 않는다.
- 준비 중인 소개·작업물·연락처 본문과 비활성 Log는 의도된 미완성 범위이다.

## 최초 공개 순서

1. GitHub에 반영하기 전 공개할 파일과 정보를 확인한다.
2. CI 검사·빌드 성공을 확인하고 필요한 표시 환경변수를 설정한다.
3. VM·DNS·HTTPS를 구성하고 빌드 결과를 새 릴리스 디렉토리에 배치한다.
4. 실제 도메인에서 홈, 자산, 없는 경로, 휴대폰 화면과 연락처를 확인한다.
5. 갱신 때는 검증된 릴리스로 전환하고 이전 릴리스를 롤백용으로 남긴다.

이 점검에서 운영 서버 배포, 커밋, 푸시, 원격 secrets 등록은 수행하지 않았다.
