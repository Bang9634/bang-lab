# 설계 결정

## Astro와 정적 생성

콘텐츠 중심 사이트이므로 정적 파일을 생성한다.
운영 환경의 실행 의존성을 줄이고 앱 서버 없이 Nginx로 서비스할 수 있다.
정적으로 처리할 수 없는 구체적인 요구사항이 생기면 다시 검토한다.

## Markdown/MDX와 콘텐츠 컬렉션

향후 Log의 글은 Git으로 관리하고 스키마로 메타데이터를 검증할 계획이다.
현재는 기존 초안의 콘텐츠 컬렉션과 템플릿을 삭제한 상태이다.
Markdown을 기본으로 사용하며 컴포넌트가 필요하면 MDX를 사용한다.
실수로 공개하는 일을 줄이기 위해 글의 기본 상태는 초안으로 설정한다.
초안 제외는 사이트 빌드에만 적용되며, 공개 저장소에 커밋한 글 원문을 숨겨주지는 않는다.
참고: [Astro 콘텐츠 컬렉션](https://docs.astro.build/en/guides/content-collections/)

## 최소한의 클라이언트 코드

초기 페이지에는 클라이언트 상태가 필요하지 않다.
React, 검색 라이브러리, 애니메이션 라이브러리와 페이지네이션은
실제 상호작용이나 콘텐츠 양이 도입을 정당화할 때 추가한다.

## 추가 빌드 관리 도구 없는 모노레포

npm workspaces로 `apps/web`의 공통 명령과 잠금 파일을 관리한다.
현재 규모에서는 별도 모노레포 빌드 프레임워크가 필요하지 않다.

## 측정 중심 학습

문제 관찰 → 가설 → 반박 → 실험 설계 → 구현 → 벤치마크/프로파일링 → 분석 → 공개 순서로 진행한다.
실제로 측정한 결과와 계획을 구분하고, 결과마다 재현 조건과 한계를 기록한다.

## 문서 언어

README, 개발 문서, `AGENTS.md`와 `docs/ai-context/`는 한글로 관리한다.
작성자가 내용을 정확히 검토하고 최신 상태로 유지하기 쉬운 언어를 우선한다.
기술 용어, 코드 식별자와 경로는 원문을 유지하고, 코드 주석과 커밋 메시지는 영어를 기본으로 한다.
한글·영문 사본을 중복 관리하지 않는다.
AI 컨텍스트의 언어를 성능이나 비용 목적으로 바꿀 때는 실제 사용 모델에서
토큰 수와 작업 성공률을 측정한 뒤 판단한다.
